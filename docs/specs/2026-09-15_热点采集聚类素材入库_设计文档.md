## 1. 目标与范围

打通后端自动化主管线的第一段：**多源热点采集 → 事件聚类落库（SQLite）→ 素材入库与形态重评估**，并通过 4 个 API 端点暴露。

**做**：
- `SignalSource` 采集协议 + FixtureSource（内置模拟信号池）+ 微博热搜真实适配器（公开 JSON，免登录）
- bigram Jaccard 标题聚类，阈值可配
- 素材双入口入库（fixture 自带 / `ingest_asset` 手动补录），暂缓事件自动重评估形态
- Event 模型扩展 timeline；SQLite 建表与 DAO；API 端点

**不做（范围外）**：定时调度、信号落库、X/抖音源、视觉密度模型、语义聚类、加权评分模型、CORS/鉴权。

## 2. 本迭代拍板决策（详见 DECISIONS.md D6–D8）

| 决策 | 结论 |
| --- | --- |
| 数据源策略 | 接口抽象 + FixtureSource + 微博热搜（策略 A） |
| 真实源 | 微博热搜 `weibo.com/ajax/side/hotSearch`（免登录公开 JSON） |
| 触发方式 | API 端点触发；调度写成可复用函数，定时轮询留后续薄封装 |
| 聚类算法 | 标题字符 bigram 集合的 Jaccard 相似度 ≥ 0.35（可配），零新依赖 |
| 素材/密度边界 | 双入口（fixture 自带 + 手动补录），密度/清晰度入库时落库、值由调用方提供，打分留可替换接口；真实源事件无素材 → 命中规则 4 → 素材等待队列 |
| 架构 | 方案一：pipeline 纯函数 + 瘦 DAO + API 薄封装（同步，无事件总线） |

## 4. 数据模型

### 4.1 RawSignal（管道内传输对象，不落库）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| title | str | 信号标题/热搜词 |
| heat | float | 热度 0–100（微博 num 按 batch min-max 归一；batch 极差为 0 时取 50；fixture 直接给定） |
| source | str | `"weibo_hot"` / `"fixture"` |
| source_url | str | 原始链接（微博：热搜词搜索页） |
| published_at | str | ISO 时间（微博取采集时刻） |
| pending_assets | list[MediaAsset] | fixture 信号可自带模拟素材（模拟“算法已识别”属性），聚类建事件时随事件入库 |

### 4.2 Event 扩展

- 新增 `timeline: list[TimelineEntry]`；`TimelineEntry = {ts, title, source, heat, source_url}`，SQLite 存 JSON 列
- `score` 语义：**归一化热度 0–100**；并入多信号时取 max（加权评分模型留后续迭代）
- `summary` 微博源无摘要，保持空串

### 4.3 SQLite 表

- `events`：id TEXT PK / title / summary / score REAL / status / timeline_json TEXT / created_at
- `media_assets`：与 `MediaAsset` 模型字段一一对应，event_id 建索引
- 映射手写（无 ORM）；`migrate()` 全部 `CREATE TABLE IF NOT EXISTS`，启动时与测试夹具中调用

## 5. 采集器

- `SignalSource` 协议：`fetch() -> list[RawSignal]`（与 PublishAdapter 同构，协议 + 注入式测试替身）
- **WeiboHotSearchSource**：
  - httpx GET `https://weibo.com/ajax/side/hotSearch`，解析 `data.realtime[]` 的 `word`/`num`
  - `client_factory` 可注入（测试用 `httpx.MockTransport`），超时 10s
  - 失败抛 `CollectorError`，由 `fetch_signals` 捕获记录，**单源失败不影响其他源**
- **FixtureSource**：内置约 30 条信号（含多组“同事件不同标题”信号专测聚类合并；含自带素材与无素材两类信号）
- `fetch_signals(sources) -> (list[RawSignal], list[SourceStatus])`；`SourceStatus = {source, ok, count, error}`

## 6. 聚类与素材入库

### 6.1 clustering.py

- `title_bigrams(s) -> set[str]`：去空白后的字符 bigram 集合
- `jaccard(a, b) -> float`：|∩| / |∪|，两集合皆空时返回 0
- `cluster_signals(signals, existing_events, threshold=0.35) -> ClusterReport`：
  - 每条信号与**所有现有事件标题**（含本批已新建事件）计算相似度，取最大者；≥ threshold → 并入（score 取 max、timeline 追加、source_url 去重、事件标题保持首条不变）
  - 无命中 → 新建事件（score = 信号热度，timeline 含首条）
  - `cluster_signals` 为**纯函数**（不碰数据库）：新建事件的初始状态按形态判定预判——`pending_assets` 中存在可用素材 → `READY`；否则规则 4 → `DEFERRED`（素材等待队列）；素材的真正落库由编排层（collect 端点）对 created 事件的 `pending_assets` 逐条调用 `ingest_asset` 完成
  - `ClusterReport = {created: list[Event], updated: list[Event], assignments: list[{signal_title, event_id, matched}]}`
- 合规约束（D2）：仅 `is_usable`（cleared 且非 C 类）素材参与形态判定，沿用 `format_decision` 现有过滤

### 6.2 asset_ingest.py

- `ingest_asset(db, event, asset) -> IngestReport`
  - 素材落库（`auth_status` 默认 `pending`；密度/清晰度由调用方提供并在入库时落库）
  - 若事件 `status == DEFERRED`：入库后对事件全部素材重跑 `decide_format`；非 DEFER → 事件转 `READY` 并落库（对应“授权补录/素材补齐自动重评估”闭环）
  - `IngestReport = {asset, decision: FormatDecision, event_status_changed: bool}`

## 7. API 端点

| 端点 | 请求 | 响应/语义 |
| --- | --- | --- |
| `POST /pipeline/collect` | body 可选 `{"sources": ["fixture", "weibo_hot"]}`，默认全跑 | 聚合多源 → 聚类 → 落库，返回 ClusterReport + SourceStatus |
| `GET /events` | query: `status`（可选）、`limit`（默认 50） | 事件列表 |
| `GET /events/{id}` | — | 详情：timeline + assets + 当前形态判定（`decide_format` 即时计算）；不存在返回 404 |
| `POST /events/{id}/assets` | 素材字段（type/clarity/info_density/source_type/auth_status/attribution/source_url 等） | ingest_asset 结果；事件不存在 404 |

- DB 生命周期：FastAPI lifespan 创建 `DB(路径)` 并 `migrate()`，挂 `app.state.db`；默认路径 `data/workflow.db`，可用环境变量 `WORKFLOW_DB` 覆盖
- 数据源工厂为 app 级依赖（`get_sources`），测试用 `app.dependency_overrides` 注入 FakeSource

## 9. 验收标准

1. `pytest` 全绿（现有 22 例 + 新增用例），`ruff check .` 零违规
2. `POST /pipeline/collect`（默认源）对 FixtureSource 端到端产出：事件落库、素材落库、状态符合形态判定口径
3. 真实微博源在本地可跑通一次采集（网络不可用时返回清晰 SourceStatus 错误，不崩服务）
4. demo 冒烟测试保持通过

## 10. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 微博接口无官方保证，字段可能变更 | 解析集中在 WeiboHotSearchSource 单类内；MockTransport 测试锁定解析契约；失败仅影响单源状态 |
| bigram 阈值 0.35 可能误合并/漏合并 | 阈值为参数可配；Fixture 内置边界用例；后续按实际信号校准 |
| 事件标题不更新导致后续信号匹配偏差 | MVP 接受（标题保持首条）；聚类溯源记录在 ClusterReport.assignments |
