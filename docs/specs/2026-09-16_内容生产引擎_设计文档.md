# 内容生产引擎（生产 + 自动质检）｜MVP 设计文档

> 状态：已评审通过（2026-09-16，用户逐节确认）。
> 配套：`热点内容自动化工作流_产品设计.md` §4.4–4.5 / §5，`docs/context/DECISIONS.md` D1/D2/D4/D8/D9，`系统设计文档.md`。
> 本文为该迭代的功能规格；实现完成后代码真实结构以 `系统设计文档.md` 回填为准。

## 1. 目标与范围

打通后端自动化主管线的第二段：**READY 事件 → 内容成品生成（模板编排）→ 自动质检（一票否决 + 质量分）→ Production 落库**，并通过 3 个 API 端点暴露。

**做**：
- `ContentComposer` 协议 + `TemplateComposer` 模板实现（标题/正文/素材编排/封面，零外部依赖）
- 独立质检纯函数：一票否决 + 确定性质量分（≥75 通过），三态 `QUALIFIED / HELD / BLOCKED`
- 生产编排：事件状态机 `READY → PRODUCED`，Production 与质检结果落库
- `production` SQLite 表与 DAO；API 端点（单事件生产 / 批量生产 / 成品查询）

**不做（范围外）**：LLM 生成器实现（仅留协议）、多版本产出（快讯/解读/垂直版）、账号自动分配与待发布队列入队（下一迭代）、held 次日重试调度、引用比例超限检查、风险标签与待确认队列、真实媒体渲染、定时调度。

## 2. 本迭代拍板决策（详见 DECISIONS.md D9）

| 决策点 | 结论 |
| --- | --- |
| 迭代范围 | 生产引擎 + 自动质检闭环（§4.4 + §4.5）；账号分配与入队留下一迭代 |
| 文本生成 | 模板为主 + `ContentComposer` 协议预留（方案 C），后续可插 LLM 实现 |
| 触发方式 | 仅 API 手动触发（单事件 + 批量），无自动联动、无事件总线（沿用 D8 方案一） |
| 模块组织 | 双模块分工（composer.py + quality_check.py + producer.py），质检独立纯函数可复用 |
| 质检口径 | 一票否决 + 确定性质量分公式；引用比例超限检查不实现（素材无原文文本可比对，假检查） |
| 事件状态机 | `READY → PRODUCED` 一次性，重复生产拒绝（409）；held/blocked 是成品质检态，重试属发布配额概念 |

## 3. 模块与文件结构

```text
app/pipeline/
  composer.py       # ContentComposer 协议、Draft、TemplateComposer
  quality_check.py  # QualityResult、VETOES 检查项、check_quality、quality_score
  producer.py       # produce_for_event / produce_all（编排层）
app/daos/
  db.py             # 扩展 migrate()：幂等建 production 表
  production_dao.py # ProductionDao：insert / get_by_event / list（状态过滤）
app/models/production.py  # 扩展字段 + QualityStatus 增加 BLOCKED
app/api/            # 3 端点（§8），FastAPI lifespan 注入 DB
```

## 4. 数据模型

### 4.1 Production 扩展（`app/models/production.py`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `body` | `str = ""` | 正文（图文/图集形态）或脚本解说词（视频形态） |
| `cover_asset_id` | `str = ""` | 封面素材 id |
| `rule` | `str = ""` | 命中的形态规则（`规则1` / `规则2` / `规则3`） |
| `composer` | `str = "template"` | 生成器标识，预留 `llm` 等 |
| `checks` | `list[str]` | 质检检查项明细 |
| `vetoes` | `list[str]` | 一票否决明细 |

`QualityStatus` 扩展为三态：`QUALIFIED`（通过，可进发布配额）/ `HELD`（留档，<75）/ `BLOCKED`（一票否决拦截）。新增枚举值 `BLOCKED = "blocked"`。

### 4.2 Draft（composer 管道内传输对象，不落库）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | `str` | 成品标题 |
| `body` | `str` | 正文/脚本 |
| `ordered_asset_ids` | `list[str]` | 素材编排顺序（图片按信息密度降序） |
| `cover_asset_id` | `str` | 封面素材 id（信息密度最高者） |

### 4.3 QualityResult（quality_check 纯函数返回值，不落库）

```python
QualityResult = {score: float, checks: list[str], vetoes: list[str], status: QualityStatus}
```

结果落在 `Production` 的 `quality_score / checks / vetoes / quality_status` 字段上，不单独建表（对应系统设计文档的 Production 1:1 QualityResult）。

### 4.4 SQLite 表

- `production`：与 `Production` 模型字段一一对应；`checks` / `vetoes` / `asset_ids` 存 JSON 列；`event_id` 建索引
- 映射手写（无 ORM）；`migrate()` 全部 `CREATE TABLE IF NOT EXISTS`

## 5. 内容生成器（composer.py）

- `ContentComposer` 协议：`compose(event, assets, decision) -> Draft`
  - 入参约定：`assets` 已经过 D2 过滤（仅 usable）；`decision` 为实时复跑的 `FormatDecision`
- `TemplateComposer` 实现：
  - **标题**：按规则选模板——规则1 `视频直击：{event.title}`、规则3 `现场实录：{event.title}`、规则2 `多图直击：{event.title}`
  - **正文**：事件摘要段（title + summary）→ 时间线段（timeline 按 ts 升序逐条）→ 素材署名段（有 attribution 的素材逐条列出）
  - **编排**：图片按信息密度降序（缺密度值视为 0 排后）；`ordered_asset_ids` = 视频（保持原序）+ 排序后图片
  - **封面**：信息密度最高的素材；无可选素材时留空串
- `Draft` 组装为 `Production` 时校验素材 id 全部存在于编排骨箱（防御性一致性）

## 6. 质检（quality_check.py）

### 6.1 一票否决（命中任一 → BLOCKED）

`check_quality(event, assets) -> QualityResult`：`assets` 为参与本成品的素材清单（生产流程传入 usable 子集）。

| 检查项 | 判定 | 映射产品文档 |
| --- | --- | --- |
| 事件来源缺失 | `event.timeline` 为空 | §4.5 事件来源完整性 |
| 素材不可用 | `assets` 为空（防御兜底） | §4.5 素材可用性 |
| 素材授权未确认 | `assets` 中混入非 usable 素材（防调用方误传全集的兜底断言） | §4.5 授权合规（D2） |
| 署名缺失 | 任一 usable 素材 `attribution` 为空 | §4.5 署名 |
| 引用比例超限 | **不实现**：素材无原文文本可比对，属于假检查；规格明确记录 | §4.5 |

### 6.2 确定性质量分（0–100，≥75 为 QUALIFIED）

```
score = 50（基础）
      + usable 素材信息密度均值 × 0.25          （0–25，缺密度值按 0 计）
      + 素材充足度：usable ≥3 张 +10，2 张 +5   （0–10）
      + 时间线完整度：timeline ≥3 条 +10，2 条 +5（0–10）
      + 标题长度 10–30 字 +5                    （0–5）
```

三态判定：`vetoes` 非空 → `BLOCKED`；无否决且 `score ≥ 75` → `QUALIFIED`；否则 `HELD`。阈值 75 与 demo 模拟口径一致。

## 7. 生产编排（producer.py）

`produce_for_event(conn, event_id, composer=TemplateComposer()) -> Production`：

1. 查事件；不存在 → `ProducerError(kind="not_found")`
2. 事件 `status != READY`（含已 PRODUCED）→ `ProducerError(kind="not_ready")`
3. 取事件全部素材并过滤 usable（D2）；再次实时复跑 `decide_format`（不读历史判定，素材变化后口径始终最新）——若结果为 DEFER（与 READY 状态矛盾，防御）→ `not_ready`
4. `composer.compose(event, usable_assets, decision) -> Draft`
5. `check_quality(event, usable_assets) -> QualityResult`
6. 组装 `Production`（`production_type` 由 `ContentFormat` 映射，`DEFER` 不可能出现）落库
7. 事件状态 `READY → PRODUCED` 落库

`produce_all(conn) -> ProduceAllReport`：批量处理全部 READY 事件（score 降序），逐个调 `produce_for_event`，**单事件失败不影响其余**（与 D6 容错同构）；返回 `{produced: list[Production], skipped: list[{event_id, reason}]}`。

## 8. API 端点

| 端点 | 请求 | 响应/语义 |
| --- | --- | --- |
| `POST /pipeline/produce` | body `{"event_id": "..."}` | 200 Production（含质检结果）；404 事件不存在；409 非 READY 或已生产 |
| `POST /pipeline/produce/all` | — | 200 `{produced: [...], skipped: [{event_id, reason}]}` |
| `GET /productions` | query: `status`（可选，qualified/held/blocked）、`limit`（默认 50） | 成品列表（留档捞回入口） |

- DB 生命周期沿用现状（lifespan 注入 `app.state.db`）
- composer 工厂为 app 级依赖（`get_composer`），测试用 `app.dependency_overrides` 注入替身

## 10. 验收标准

1. `pytest` 全绿（现有 71 例 + 新增用例），`ruff check .` 零违规
2. Fixture 事件端到端：`POST /pipeline/collect` →（必要时补录素材转 READY）→ `POST /pipeline/produce` 产出 Production，质检三态与公式口径正确，事件状态转 PRODUCED
3. `POST /pipeline/produce/all` 对混合状态事件集批量产出，失败事件进 skipped 不中断
4. demo 冒烟测试保持通过（本迭代不改 demo）

## 11. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 模板文本单调，产出质量上限低 | MVP 明确接受（产品口径：模板为主）；ContentComposer 协议预留 LLM 插槽，替换不动数据流 |
| 质量分公式主观 | 公式各分项写明依据（密度/充足度/时间线/标题），测试锁定分项贡献；后续可按运营反馈调权 |
| 实时复跑形态判定与历史 READY 状态矛盾 | 防御路径返回 not_ready，批量中进 skipped，不静默吞掉 |
| Production 与事件状态跨表更新非原子 | SQLite 单连接 + 事务（沿用现有 db.py 模式），测试覆盖 |
