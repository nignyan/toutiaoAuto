# 数据回流 设计文档（D15）

> 2026-09-16 迭代规格。需求源：产品设计文档 §4.7（数据回流）+ §4.6「记录审核状态」（D13 移交）；前置：D13 已完成发布执行闭环（队列 published 终态）。本迭代补齐流水线最后一环：**表现数据汇总 → 多维分析 → 建议动作人工确认**，不自动调参（D3）。

## 1. 范围

**做**：
- 表现数据回填：每个**已发布**成品的曝光/播放/完播率/互动/负反馈 + 平台审核状态（审核通过/驳回），人工录入（头条号无个人 API，无自动采集来源）。
- 多维分析（纯函数）：按**内容形态 / 发布时段 / 热点垂类 / 标题长度**四维聚合表现指标。
- 建议动作：由分析结果确定性生成（形态/时段/垂类三类），运营**确认 / 驳回 / 回滚**（回滚 → 回到待确认，可再采纳——2026-09-16 用户拍板），不自动调整任何权重。
- 发布时间数据：`publish_queue` 新增 `published_at`（confirm / auto_publish 派发成功时落库），供时段分析。

**不做（显式出界）**：
- 自动调参：反哺热点评分 / 账号选题偏好 / 模板排序仅以建议文案呈现，不落任何权重（D3，§7 演进项：单次调幅 ≤15%、观察期 7 天、一键回滚）。
- 表现数据自动采集（RPA 抓头条后台数据页）：选择器未校准，MVP 人工回填。
- 多次快照：每成品**单条记录 upsert**，重复回填覆盖更新（汇总口径取最新数——2026-09-16 用户拍板）；指标随时间演进追踪列演进项。
- 素材来源回流：成品 `asset_ids` 已关联素材（source_type 可查），不在回流分析中单列。
- LLM 建议文案、垂类自动分类（`vertical` 沿用 D10，MVP 多为空）。

## 2. 数据模型

### 2.1 表现记录（reflux_records，每成品 1:1）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PK | |
| production_id | TEXT UNIQUE | 1:1 兜底唯一索引 |
| account_id | TEXT | 冗余自队列项，免联查 |
| exposure / plays / interactions / negative | INTEGER ≥0 | 曝光 / 播放 / 互动合计 / 负反馈 |
| completion_rate | REAL 0–100 | 完播率（百分比口径，与平台后台一致） |
| review_status | TEXT | 平台审核：`pending_review` / `approved` / `rejected`，默认 pending_review |
| review_note | TEXT | 审核备注（如驳回原因） |
| recorded_at | TEXT | 本次回填时间（upsert 刷新） |
| created_at | TEXT | 首次回填时间 |

### 2.2 建议动作（reflux_suggestions）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PK | |
| kind | TEXT | `format`（形态）/ `timing`（时段）/ `vertical`（垂类） |
| text / basis / impact | TEXT | 建议文案 / 数据依据摘要 / 预期影响 |
| status | TEXT | `pending` / `confirmed` / `rejected` |
| created_at / decided_at | TEXT | decided_at 首次决策时落 |

**状态机**：`pending → confirmed`（采纳）、`pending → rejected`（驳回）、`confirmed → pending`（回滚，撤销采纳后重新待确认——拍板口径）。非法流转 409。

## 3. 分析口径（纯函数）

- 输入：表现记录 join 成品（形态/垂类/标题）+ 队列项（published_at）；`published_at` 为空的老数据不参与时段分析。
- 分组维度：
  - **内容形态**：`production.production_type`（video / image_slideshow / text）
  - **发布时段**：`published_at` UTC 小时 → 4 桶（00–06 / 06–12 / 12–18 / 18–24）
  - **热点垂类**：`production.vertical`（空串 = 通用，单列展示但不参与垂类建议）
  - **标题长度**：标题字符数 3 桶（≤15 / 16–25 / >25）
- 组内指标：条数、平均曝光/播放/完播率、**互动率**（Σ互动/Σ曝光×100）、负反馈率（Σ负反馈/Σ曝光×100）。
- 排序基准指标：**互动率**（MVP 唯一排序基准；曝光/完播仅展示）。

### 3.1 建议生成规则（确定性，常量可调）

- `MIN_GROUP_SAMPLE = 2`：参与比较的组样本 ≥ 2 条。
- `MIN_RELATIVE_GAP = 0.30` 且绝对差 ≥ 1 个百分点：最优组互动率相对最差组高出 30% 且最差组互动率 > 0 才生成建议，避免小样本/零分母噪声。
- 每维度至多 1 条建议（最优组 vs 最差组，统一比较规则）；样本不足或差距不够则该维度不产出。
- 垂类维度排除空串（通用）组，且需 ≥2 个非通用垂类才可比较；不满足则不产出。

## 4. 编排与触发

- 模块：`app/pipeline/reflux.py`（producer/allocator/dispatcher 同构：错误类型 + 纯函数 + 编排函数）。
- `record_performance(db, payload) -> PerformanceRecord`：
  1. 成品不存在 → `RefluxError(not_found)`；队列项不存在或非 `published` → `RefluxError(not_published)`（API 映射 404 / 409）。
  2. upsert 落库（`db.run` 单表原子）；`account_id` 冗余自队列项。
- `analyze(db) -> AnalysisReport`：
  1. 重算分析报告（纯函数 `build_report`）。
  2. **重建待确认建议**：删除现存 `pending` 建议后插入新生成项；`confirmed` / `rejected` 保留作决策历史（数据未变时重复 analyze 会产生同文 pending 项，属预期，MVP 不做去重）。
  3. 删除 pending + 插入建议在 `db.transaction()` 内（注意：事务内只用 `*_with(conn)`，预检在事务外——D13 死锁教训）。
- 触发：仅 API 手动触发（回填 / 分析），无定时器（沿用 D8–D13 方案一）。

## 5. API（新增 8 端点，总 29）

| 端点 | 语义 | 错误码 |
| --- | --- | --- |
| `POST /reflux/records` | 回填表现数据（upsert）+ 审核状态 | 404 成品不存在；409 队列项非 published |
| `GET /reflux/records` | 记录列表（含成品标题/形态/发布时间，回填时间降序） | — |
| `POST /reflux/analyze` | 重算分析 + 重建待确认建议，返回报告 + 建议 | — |
| `GET /reflux/analysis` | 只读分析报告（不重建建议） | — |
| `GET /reflux/suggestions` | 建议列表，可按 status 过滤 | — |
| `POST /reflux/suggestions/{id}/confirm` | 采纳（pending → confirmed） | 404；409 非 pending |
| `POST /reflux/suggestions/{id}/reject` | 驳回（pending → rejected） | 404；409 非 pending |
| `POST /reflux/suggestions/{id}/rollback` | 回滚（confirmed → pending） | 404；409 非 confirmed |
