## 1. 目标与范围

打通自动化主管线的第三段：**QUALIFIED 成品 → 账号自动分配（垂类/角色域/当日配额）→ 待发布队列入队**，并通过 7 个 API 端点暴露（账号管理 4 + 入队与查询 3）。

**做**：
- `Account` 模型扩展角色域 `role`（主域/测试域/实验域，§4.6 多域结构）
- `account` 表 + `AccountDao`（新建/查询/编辑/删除）；`publish_queue` 表 + `PublishQueueDao`
- 分配编排 `allocator.py`：`pick_account` 纯函数 + `allocate_for_production` + `enqueue_all`（批量容错）
- 分配成功原子回填 `production.account_id`；`Production` 增加 `vertical` 字段支撑垂类匹配
- API 端点（§7）

**不做（范围外）**：队列状态流转（提交发布/跳过/失败，属发布执行迭代）、RPA 填稿联动、held 次日重试调度、账号垂类自动分类（事件侧垂类标签来源）、定时调度、LLM 生成器、多版本产出。

## 2. 本迭代拍板决策（详见 DECISIONS.md D10）

| 决策点 | 结论 |
| --- | --- |
| 迭代范围 | 分配 + 入队闭环（产品文档 §4.6 上半段）；发布执行留下一迭代 |
| 触发方式 | 仅 API 手动触发（单成品 + 批量），无事件总线（沿用 D8/D9 方案一） |
| 角色域 | `Account.role`: `primary`（主域）/ `test`（测试域）/ `experiment`（实验域）；**测试域不参与自动分配**（产品文档分配优先级链仅含主域/实验域，测试域内容人工控制） |
| 成品垂类 | `Production.vertical`（默认 `""`=通用）；MVP 无事件垂类分类来源，API 生产流恒为空 → 精确匹配层级策略完整实现但通常不触发，字段为后续就绪 |
| 配额口径 | `daily_quota` = 当日入队上限；已用 = 当日（UTC 日期）该账号队列条目数，跳过/失败不释放；`quota=0` 视为不参与分配 |
| 队列幂等 | production 与队列项 1:1（`UNIQUE(production_id)`），重复入队拒绝（409） |
| 批量顺序 | `enqueue_all` 按质量分降序（配额紧张时优质内容优先，与 `produce_all` 分数优先同构） |
| 发布窗口 | MVP 不参与分配判定；队列项 `scheduled_for` 留空 |
| 账号删除 | 仅实验域可删（产品文档「实验域可删」）；存在 PENDING 队列项时拒绝删除 |

## 4. 数据模型

### 4.1 Account 扩展（`app/models/account.py`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `role` | `AccountRole` | 角色域：`PRIMARY`（主域，默认）/ `TEST`（测试域）/ `EXPERIMENT`（实验域） |

### 4.2 Production 扩展（`app/models/production.py`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `vertical` | `str = ""` | 成品垂类标签；空 = 通用，不参与精确匹配 |

### 4.3 SQLite 表

- `accounts`：与 `Account` 模型一一对应；`auto_publish` 存 INTEGER（0/1）
- `publish_queue`：与 `PublishQueueItem` 一一对应；`production_id` 建唯一索引（1:1 幂等）；`account_id` 建索引
- 存量库迁移：`production` 表补 `vertical` 列（`PRAGMA table_info` 检查 + `ALTER TABLE ADD COLUMN`，幂等；新库直接建全列）

## 5. 分配策略（allocator.py）

### 5.1 候选资格（三条同时满足）

1. `status == ACTIVE`（暂停账号不分配）
2. `role != TEST`（测试域不参与自动分配）
3. 当日已用配额 < `daily_quota`（`quota=0` 不参与；已用 = 当日 UTC 日期 prefix 的队列条目数，各状态均计数）

### 5.2 分配层级（垂类精确匹配 > 通用主域 > 实验域）

| 层级 | 条件 |
| --- | --- |
| 0 垂类精确匹配 | `production.vertical != ""` 且 `account.vertical == production.vertical` |
| 1 通用主域 | `role == PRIMARY` |
| 2 实验域 | `role == EXPERIMENT` |

同层级内按 `created_at` 升序 + `id` 稳定排序（先配置的账号优先，结果确定可测）。

`pick_account(production, accounts, used_quota) -> Account | None` 为纯函数；无合格候选返回 `None`。

### 5.3 编排

`allocate_for_production(db, production_id) -> PublishQueueItem`：

1. 查成品；不存在 → `AllocationError("not_found")`
2. `quality_status != QUALIFIED` → `AllocationError("not_qualified")`
3. 已存在队列项（1:1）→ `AllocationError("already_enqueued")`
4. `pick_account` → `None` → `AllocationError("no_account")`
5. `db.transaction` 内原子：队列项落库 + `production.account_id` 回填

`enqueue_all(db) -> EnqueueAllReport`：批量处理全部未入队 QUALIFIED 成品（质量分降序，`created_at` 升序决胜），逐个调 `allocate_for_production`，**单成品失败不影响其余**（与 D6/D9 容错同构）；返回 `{enqueued: list[PublishQueueItem], skipped: list[{production_id, reason}]}`。每成功一单配额即时生效（编排层逐次重算当日用量，不预计算缓存）。

## 6. 账号管理语义

- 新建：`name` 必填；`role` 默认主域；`daily_quota` 默认 0（须显式配置才参与分配）
- 编辑（PATCH）：部分字段更新；暂停/恢复走 `status`；域设置保存后立即生效（下次分配即按新值）
- 删除：仅实验域；存在 PENDING 队列项时拒绝（409），防悬空待办
- `channel` / `adapter` / `auto_publish` / `profile_dir` 随模型默认，发布执行迭代使用

## 7. API 端点

| 端点 | 请求 | 响应/语义 |
| --- | --- | --- |
| `POST /accounts` | body 账号字段（name 必填） | 200 Account |
| `GET /accounts` | query `status`（可选） | 账号列表 |
| `PATCH /accounts/{id}` | body 部分字段 | 200 账号；404 不存在 |
| `DELETE /accounts/{id}` | — | 200 `{deleted}`；404 不存在；409 非实验域或有 PENDING 队列项 |
| `POST /pipeline/enqueue` | body `{"production_id": "..."}` | 200 PublishQueueItem；404 成品不存在；409 非 QUALIFIED / 已入队 / 无可用账号 |
| `POST /pipeline/enqueue/all` | — | 200 `{enqueued: [...], skipped: [{production_id, reason}]}` |
| `GET /publish-queue` | query `account_id` / `status`（可选）、`limit`（默认 50） | 队列列表（`created_at` 升序 = 投递顺序） |

- DB 生命周期沿用现状（lifespan 注入 `app.state.db`）

## 10. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 配额按 UTC 日切分与运营本地日不一致 | MVP 明确记录口径；后续如需按本地时区切分只改 `used_quota_today` 取日期一处 |
| 存量库缺 vertical 列导致查询失败 | 迁移用 `PRAGMA table_info` 幂等补列，测试覆盖旧库升级路径 |
| 测试域账号永不自动入队造成困惑 | 规格/决策文档明示口径：测试域内容人工控制 |
| 分配与回填跨表非原子 | 沿用 `db.transaction` + `UNIQUE(production_id)` 兜底，测试覆盖 |
